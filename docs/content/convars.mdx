tLib has **no config file**. Everything an owner can change is a convar in `server.cfg`,
placed **above** `ensure tLib`. If a convar is not on this page, tLib does not read it.
Every duration carries its unit in the name (`_ms`); there are no unit-less aliases.

## `set` vs `setr`

`set` defines a convar the **server** can read. `setr` also replicates it to every connected
**game client**. A convar read by client Lua or by the NUI needs `setr`; one read only by
the server bundle uses `set`.

Getting it wrong fails *quietly*:

- A `setr` convar written with `set` makes the client read the built-in default. Point
  `tlib_api_base_url` at your own host with `set` and the server talks to your host while
  the in-game panel keeps talking to ours.
- A `set` convar written with `setr` works, but ships the value to everyone who joins.
  Never do it for a secret.

## Demo mode

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_demo` | `set` | boolean — `1`, `true`, `yes`, `on` | *(off)* | Turns the server into a self-resetting showroom. **Every player becomes a superadmin and every access gate opens**, no resource writes its data file, and marketplace installs are swept at the next start. |

`setr` also works and does no harm.

<Callout type="warning">
**Demo mode is fail-open, and it is the only thing in tLib that is.** Anyone who connects
can do anything, including install marketplace content and change every server setting.
Never set it on a server whose data you care about or whose players you do not. tLib prints
a red banner at boot for as long as it is on.
</Callout>

| | In demo mode |
| --- | --- |
| Server settings, layouts, codeplugs, vehicle configs — anything in a `data.json` | Held in memory for the session, never written. Back to the shipped file on restart. |
| Marketplace items a visitor installs | Really installed, so they work; swept at that resource's next start. |
| **Preinstalled** marketplace content shipped in the zip | **Untouched.** |
| Per-player client storage (HUD placement, menu preferences) | **Untouched.** It lives on the player's machine. |

Nothing is deleted — writes are dropped, not rolled back — so removing the convar and
restarting brings the server back exactly as it was.

`tlib_demo [on|off|convar]` (console, or a player holding `command.tlib_demo`) changes it live and reports the new
state; `convar` stops overriding and follows `server.cfg` again. Access and permission
changes take effect immediately; the **data reset and the marketplace sweep** happen when a
resource starts.

## Diagnostics

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_telemetry` | `set` | boolean — `1`, `true`, `yes`, `on`, `enabled` / `0`, `false`, `no`, `off`, `disabled` | *(unset — off)* | Opt in to **diagnostics events**: errors, warnings, renderer crashes and slow-operation outliers from our own code, with machine context. This convar is the only control. |
| `tlib_telemetry_key` | `set` | string | *(empty)* | Dev only: points the transport at a local ingest credential. There is nothing for an operator to supply. |

**`tlib_telemetry` is the only way to turn diagnostics on or off.** Unset is **off**, and an
unreadable value (`maybe`) still counts as a decision, leaving it **off**. A consumer
resource can store an answer of its own with `SetTelemetryConsent` (see
[Exports](/docs/tLib/exports)), and this convar, once set, overrides it.

`tlib_telemetry_status` in the server console reports what is enabled, what decided it, how
much is queued, and whether the transport has given up for this session.

[Diagnostics](/docs/tLib/telemetry) is the whole account: the five event kinds, what is
never sent, and the per-install id this convar does not control. Read it before deciding.

## Marketplace

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_api_base_url` | `setr` | URL, no trailing slash, no `/api` suffix | `https://timmygstudios.com` | **Where the TIMMYG Studios API lives**: browse, preview, install downloads, community configs and the startup version check all follow it. Read by the server bundle **and** by client Lua, so `set` alone leaves the in-game panel on the default host. |

<Callout type="info">
**It covers version checks and changelogs too.** The GitHub release check some resources
use instead is **not** affected.
</Callout>

<Callout type="info">
**The value is normalised and takes effect immediately.** A trailing slash is stripped, and
so is a trailing `/api`, `/api/v1`, `/api/v2` or `/api/v2/marketplace`; a one-line warning
prints when that happens, and an empty value falls back to the default. A `setr` from the
console applies with no restart.
</Callout>

<Callout>
**The marketplace needs no credential and no setup.** Browse, preview, install and
community-config publish all work on a fresh install with nothing in your `server.cfg`.
</Callout>

## HTTP router

All server-read; none needs replicating. **None of them has to be set.** The hub and every
mounted app are reachable out of the box at `http://<your server>:<server port>/tLib/`, on
your FiveM server port — whatever `endpoint_add_tcp` declares, 30120 on a default install.
That port is already open — it is how players connect — so nothing is opened,
forwarded or declared. tLib prints the address at startup and the page links every app that is
running.

Each app answers under **its own resource name**, because that is how the FiveM server decides
which resource a request belongs to: the first part of the path is the resource, and nothing else
can claim it. The same name is used on tLib's own listener, so **the path is identical on both
doors**, and both are case-insensitive:

| App | Path, on either door |
| --- | --- |
| The hub | `/tLib/` on the server port, `/` on the listener |
| tRadio's dispatch panel | `/tRadio/` |
| tRadio's admin panel | `/tRadio/admin` |
| tDB's admin UI | `/tDB/` |

Start at the hub and follow the links rather than typing these: it always lists what is actually
running. `/tLib/tRadio/` is deliberately a 404 — the hub's door serves the hub only.

On the listener, the dispatch panel's old `/dispatch` and tDB's old `/db` still answer, with a
permanent redirect to the paths above.

The server-port door has four limits, and **tLib's own listener — which binds only if you ask for
it, and then has to be opened by hand — has none of them**. It is the route for a dispatch panel
worked all day, a federation host, or a custom domain; see
[Installation](/docs/tLib/installation#advanced-tlibs-own-listener).

- No WebSocket: tRadio's dispatch panel falls back to long-polling, which works at roughly five
  times the latency (58 ms against 11 ms, median).
- 8 KB per message from the browser; a larger one drops the connection, so a big upload through an
  admin panel can fail.
- No PocketBase realtime — tDB's SSE subscriptions do not work here, though its admin UI and REST
  API do.
- Every absolute URL tLib publishes names **one** door, and the listener wins whenever one is
  configured. So if you add a listener, Discord OAuth redirects and the tRadio desktop app's
  update download move to it and it has to be reachable from outside. With no listener they name
  this door, which needs nothing.

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_http_ingress` | `set` | `true` / `false` | `true` | Serve on the FiveM server port, as described above. `false` leaves that port alone, for tLib and for every app that mounts on it. |
| `tlib_http_port` | `set` | integer, 1–65535 | *(empty — no listener)* | tLib's own listen port, for the optional full-capability door. **Unset, no listener binds at all** and the FiveM server port is the only door. Set it and the listener binds, exactly as it did on every earlier version. A value that is not a usable port still binds, on `7777`, since a typo is not a request to go without a listener. **Setting it to your FiveM server port behaves exactly as leaving it unset** — that port already serves everything, and a second listener on it is neither possible nor needed. |
| `tlib_http_host` | `set` | bind address | *(empty — no listener)* | Interface the listener binds. Setting this and nothing else binds the listener on `7777`: naming an interface says where the listener goes, so tLib takes it as asking for one. |
| `tlib_http_public_url` | `set` | host, `host:port` or full URL | *(empty — auto-detect)* | The address clients are told to use. A bare IP or localhost implies HTTP and the listener port; a bare domain implies `https://`. Advertised, not bound. |
| `tlib_realtime_public_url` | `set` | `ws://` / `wss://` URL | *(empty — derived)* | Overrides the realtime WebSocket URL handed to clients. Realtime is a mount on the router at `/rt`; the removed `tlib_realtime_port` and `tlib_realtime_host` do nothing. |

## Menu

All read by client Lua, so all need `setr`. Changing `tlib_menu_search_key` needs a restart,
not a reload. Out-of-range or non-numeric values fall back to the default rather than erroring.

<Callout type="warning">
  **tLib does not bind a key that opens a menu, and has no command that opens one.** Whichever
  resource registers the menu owns that — it calls `RegisterKeyMapping` in its own start-up and
  then `OpenMenu`. tLib used to bind `F1` itself, on every server that installed it, menu or
  no menu; `F1` is the framework menu key on ESX and QB, and FiveM runs *every* command bound to
  a key, so one press opened the framework's menu and an empty tLib one on top of it.

  `tlib_menu_command`, `tlib_menu_key`, `tlib_menu_pad_key`, `tlib_menu_label` and
  `tlib_menu_key_slots` are gone with it. If your `server.cfg` still sets them they do nothing —
  set the key in the menu resource's own config instead (in tMenu that is `Config.MenuKey`).
</Callout>

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_menu_search_key` | `setr` | key name | `F3` | Toggles search **inside an open menu**. The one key tLib owns, so it is the same in every menu built on it; it does nothing while no menu is open. |
| `tlib_menu_locale` | `setr` | locale code | `en` | UI language. |
| `tlib_menu_request_timeout_ms` | `setr` | ms, 1000–60000 | `10000` | How long a snapshot/action request waits before failing. |
| `tlib_menu_permission_refresh_ms` | `setr` | ms, 1000–60000 | `5000` | How often permission-filtered menus are re-pushed. |
| `tlib_menu_highlight_settle_ms` | `setr` | ms, 0–2000 | `120` | Delay before a highlight change counts as settled. `0` fires immediately. |

## HUD and storage

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_hud_profile` | `setr` | string | *(empty — the server endpoint)* | Namespaces each player's saved HUD placement. Set it when one community runs several endpoints that should share one layout. |
| `tlib_community_id` | `setr` | string, `[A-Za-z0-9_-]` only | *(empty — falls back to `sv_projectName`)* | Prefix for tLib's KVP keys, separating **your** community's player storage from another community's. It does **not** separate two of your own servers: that is a per-key `serverScoped` opt-in inside the resource, not a convar — see [Import modules → kvp](/docs/tLib/import-modules). Left empty (the default, since neither this nor `sv_projectName` is a standard FiveM convar) keys are stored with no prefix. Disallowed characters are stripped; a value that strips to nothing falls through to `sv_projectName`. Read by client Lua **and** the server bundle. |

## Not convars

These look similar and are not convars. Do not put them in `server.cfg`:

| Name | What it actually is |
| --- | --- |
| `tlib_min_version`, `tlib_module`, `tlib_modules` | `fxmanifest.lua` metadata keys on the **consuming** resource. |
| `tlib_build` | A `fxmanifest.lua` metadata key **tLib's release writes into its own manifest**: a content hash of the download, so a `<resource>_diag` line can tell two builds with the same version number apart. Do not set, edit or remove it — an edited one is a lie about which files you have. Absent means the copy was not cut by a release. |
| `tlib_menu_selftest`, `tlib_menu_refresh`, `tlib_menu_permissions` | Console commands. |
| `tlib_demo` *(as a command)* | Also a console command, `tlib_demo [on\|off\|convar]`, toggling the convar above at runtime. The convar is the real setting. |
| `tmarketplace_resource_secret` | Nothing reads it. An earlier version of this page listed it as required; delete the line if you have it. |
| `tlib_menu_request_timeout`, `tlib_menu_permission_refresh`, `tlib_menu_highlight_settle` | Unit-less near-misses for the three `_ms` convars. Nothing reads them. |
