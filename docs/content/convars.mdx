tLib has **no config file**. Everything an owner can change is a FiveM convar in
`server.cfg`, placed **before** `ensure tLib`. Every one of them is `tlib_*`, and this page
is the whole surface: if a convar is not listed here, tLib does not read it.

Every duration convar carries its unit in the name (`_ms`). There are no unit-less aliases.

## `set` vs `setr` — read this first

`set` defines a convar the **server** can read. `setr` additionally replicates
it to every connected **game client**.

The rule is mechanical: a convar read by client Lua or by the NUI needs `setr`.
A convar read only by the server bundle uses `set`.

Getting it wrong fails *quietly*, which is why the column below is not decorative:

- A `setr` convar written with `set` makes the client read return the built-in
  default. Point `tlib_api_base_url` at your own host with `set` and the
  server talks to your host while the in-game panel keeps talking to ours.
- A `set` convar written with `setr` still works, but it ships your server's
  networking details to everyone who joins. Never do it for a secret.

## Demo mode

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_demo` | `set` | boolean — `1`, `true`, `yes` or `on` | *(off)* | Turns the server into a self-resetting showroom. **Every player becomes a superadmin and every access gate opens**, no resource writes its data file, and marketplace installs are swept off disk at the next start. |

`setr` also works and does no harm: the server pushes the state to clients, so a client
never reads the convar itself.

### What it is for

A public demo box that cleans itself on `ensure <resource>`, and — because it is
the same artifact you ship — a test server with nothing patched out of it. A convar
cannot travel inside a release, so the demo box keeps demo mode across every update
with no per-release edit and no build flag.

### Read this before you set it

Demo mode is **fail-open**, and it is the only thing in tLib that is. Everything
else here fails closed; demo mode overrides all of it. Anyone who
connects can do anything, including install marketplace content and change every
server setting. Never set it on a server whose data you care about or whose
players you do not.

tLib prints a red banner at boot and every 30 minutes for as long as it is on.

### What it does and does not reset

| | In demo mode |
| --- | --- |
| Server settings, layouts, codeplugs, vehicle configs — anything in a resource's `data.json` | Held in memory for the session, never written. Back to the shipped file on restart. |
| Marketplace items a visitor installs | Really installed, so they work; swept at the next start of that resource. |
| **Preinstalled** marketplace content shipped in the zip | **Untouched.** It is covered by the release's protected inventory and is never receipt-owned, so the sweep cannot see it. |
| Per-player client storage (HUD placement, menu preferences) | **Untouched.** It lives on the player's own machine and is not server state. |

Nothing is deleted — writes are dropped, not rolled back — so removing the
convar and restarting brings the server back exactly as it was.

### Flipping it on a running server

`tlib_demo [on|off|convar]` (console, or `tlib.admin`) changes it live and
reports the new state. `convar` stops overriding and follows `server.cfg` again.

Access and permission changes take effect immediately. The **data reset and the
marketplace sweep cannot** — both happen when a resource starts — so the command
says so every time it is used. To test that a marketplace install survives a
restart, turn demo mode off and restart the resource.

## Diagnostics

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_telemetry` | `set` | boolean — `1`, `true`, `yes`, `on`, `enabled` / `0`, `false`, `no`, `off`, `disabled` | *(unset — off)* | Opt in to **diagnostics events**: errors, warnings, renderer crashes and slow-operation outliers from our own code, with machine context. **This convar is the only control** — see below. ⚠️ It does not govern the per-install id, which accompanies **all** requests tLib makes to timmygstudios.com whether diagnostics are on or off — see below. |
| `tlib_telemetry_key` | `set` | string | *(empty)* | Dev only: points the transport at a local ingest credential. There is nothing for an operator to supply; the shipped build authenticates with the same public key every other studio API call uses. |

**This convar is the only way to turn diagnostics on or off.** There is one
fact and one control:

- `tlib_telemetry` **set** — that is the answer. Setting it to something
  unreadable (`maybe`) still counts as a decision: diagnostics stay **off**, with
  the value you wrote reported back to you.
- `tlib_telemetry` **unset** — **off**. No diagnostics are collected and none
  are sent. (A consumer resource can call `SetTelemetryConsent` to store an
  answer of its own — see [Exports](/docs/tLib/exports) — and this convar, once set,
  overrides it.)

`set`, not `setr`: the server decides, re-checks before every outbound request, and
pushes the answer to clients so they stop collecting. A client never reads this convar.

### ⚠️ What this convar does *not* cover: the per-install id

Marketplace browse, installs and previews, community configs and the startup
update check all run **regardless of this setting** — they are things your
server asked for, not diagnostics. Every one of them, and the diagnostics ingest
too, carries a random per-install id (`x-install-id`) so that one server can be
rate-limited or blocked at our end without affecting anybody else's.

So an install that never turns diagnostics on is still identifiable *as an
install* on the requests it chooses to make. The id is random, generated on your
own server from no input at all, and is never an IP, a licence key, a server name
or a player identifier. It lives in tLib's `data.json`; deleting it only mints a
new one, which makes your server look like a different install — it is not an
opt-out. The opt-out for diagnostics is this convar.

### Where to see the current state

`tlib_telemetry_status` in the server console. It is the only place, and it is
the authoritative answer: what is enabled, what decided it, how much is queued
and whether the transport has given up for this session.

⛔ **tLib's hub does not show this, and does not change it.** The page at
`http://<server>:7777/` (`tlib_http_port`) is app discovery and nothing else: it
has no form, no button and no JavaScript, and `POST /` is rejected outright. The
hub binds `0.0.0.0` by default and its index carries no auth, so a control there
would be one anybody who could reach the port could use.

### What is collected

Faults in **our** code and performance on real machines — five event kinds, and
nothing else:

| Event | Carries |
| --- | --- |
| `tlib.error_reported` | the resource and version, which VM the fault was in, an error kind, the error name, a file-and-line location, a hash of the normalised stack — and the scrubbed stack itself, stored once per hash per day |
| `tlib.warning_reported` | the same context, a warning kind and a warning code. **No message:** a warning's text has nowhere to go |
| `tlib.crash_reported` | a crash kind and how long the session survived. Sent on the NEXT start, because the renderer that died could not send anything |
| `tlib.slow_operation` | which operation, how long it took and the budget it crossed. **Outliers only** — never one row per call |
| `tlib.environment_reported` | once per boot: OS, a RAM bucket, GPU vendor and model, CPU threads |

### What is deliberately not

No IP, no `sv_licenseKey`, no server name, no server endpoint, no player name,
licence, Steam or Discord id, and no player count. The only identifier is the
random per-install id described above — generated on your own server from no
input at all, and sent on every studio request rather than only these.

Before anything is sent: home-directory paths lose the account name,
credential-shaped values are blanked, and anything shaped like a FiveM player
identifier (`steam:`, `license:`, `discord:`, a bare Steam id or snowflake, an
IP address) is removed. ⚠️ The store's own character set *allows* those values;
they are stripped on the way out regardless.

And four things that **could** be collected are not, because the store has no
column for them: the CEF build, the screen size, the device pixel ratio and the
JS heap limit. They still appear in the F8 console if you need them for a report.

⚠️ The RAM bucket is honest rather than precise: the browser API it comes from
caps its answer at 8 GB, so it can say "under 8 GB" or "cannot tell" and nothing
in between. A machine with 64 GB reports `unknown` rather than a wrong bucket.

⛔ **`<resource>_diag` output is not routed into this.** Those diagnostics are
operator-error reports — a bad config key, a missing file — and they stay in your
own console.

## Marketplace

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_api_base_url` | `setr` | URL, no trailing slash, no `/api` suffix | `https://timmygstudios.com` | **Where the TIMMYG Studios API lives** — not just the marketplace. One switch: browse, preview, install downloads, community configs **and** the startup version check with its changelog all follow it. Point it at a local `wrangler dev` worker for integration testing. Read by the server bundle **and** by client Lua, so `set` alone leaves the in-game panel on the default host. |

<Callout type="info">
  **It covers version checks and changelogs too.** Marketplace traffic and the startup
  update check are the same host and the same API surface (`/api/v1`, `/api/v2`,
  `/api/products`), and one convar points all of it somewhere else.

  The GitHub release check that some resources use instead is **not** affected —
  that one really does point at GitHub.
</Callout>

<Callout type="info">
  **The value is normalised, and the change takes effect immediately.**

  A trailing slash is stripped, and so is a trailing `/api`, `/api/v1`, `/api/v2`
  or `/api/v2/marketplace` — the callers append those themselves, so taking such
  a value literally would build `.../api/v1/api/v1/items`, a 404 that reads as a
  broken dev server. A one-line warning is printed when that trimming happens.
  An empty value falls back to the default rather than producing a relative URL.

  Nothing caches the resolved value, on either side, so a `setr` from the console
  applies without a resource restart.
</Callout>

<Callout>
  **The marketplace needs no credential and no setup.** Browse, preview,
  install and community-config publish all work on a fresh install with nothing
  in your `server.cfg`.

  The value the server presents as `X-Resource-Secret` is compiled into the
  resource rather than configured. It is a **public key**, shared by every install,
  and it is not specific to the marketplace: it authenticates every
  timmygstudios.com API tLib calls, the same way `tlib_api_base_url` points all of
  them at one host. What tells one server from another is the per-install id in the
  [Diagnostics](#diagnostics) section, not the key.
</Callout>

## HTTP router

All server-read. The resolved public URL is sent to clients over the wire, so
none of these needs replicating.

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_http_port` | `set` | integer, 1–65535 | `7777` | The one external listen port. |
| `tlib_http_host` | `set` | bind address | `0.0.0.0` | Interface the listener binds. |
| `tlib_http_public_url` | `set` | host, `host:port` or full URL | *(empty — auto-detect)* | The address clients should be told to use. Bare IP/localhost implies HTTP and the listener port; a bare domain implies `https://`. An advertised address, not a bind address, and not proof of reachability. |
| `tlib_realtime_public_url` | `set` | `ws://` / `wss://` URL | *(empty — derived from the router)* | Overrides the realtime WebSocket URL handed to clients. Realtime is a mount on the router at `/rt`; the removed `tlib_realtime_port` and `tlib_realtime_host` do nothing. |

## Menu

All read by client Lua, so all need `setr`. `tlib_menu_key` and
`tlib_menu_pad_key` are read during resource start because `RegisterKeyMapping`
only takes effect then — changing them needs a restart, not a reload.

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_menu_command` | `setr` | string | `tlibmenu` | Chat/console command that opens the menu. |
| `tlib_menu_key` | `setr` | key name | `F1` | Default keyboard binding. |
| `tlib_menu_pad_key` | `setr` | pad control name | `start_index` | Default controller binding. |
| `tlib_menu_search_key` | `setr` | key name | `F3` | Opens search. |
| `tlib_menu_label` | `setr` | string | `Open Menu` | Label shown in FiveM's key-binding settings. |
| `tlib_menu_key_slots` | `setr` | integer, 0–16 | `8` | How many per-item quick-bind slots are offered. `0` disables them. |
| `tlib_menu_locale` | `setr` | locale code | `en` | UI language. |
| `tlib_menu_request_timeout_ms` | `setr` | milliseconds, 1000–60000 | `10000` | How long a snapshot/action request waits on the server before failing. |
| `tlib_menu_permission_refresh_ms` | `setr` | milliseconds, 1000–60000 | `5000` | How often permission-filtered menus are re-pushed. |
| `tlib_menu_highlight_settle_ms` | `setr` | milliseconds, 0–2000 | `120` | Delay before a highlight change is treated as settled. `0` fires immediately. |

Out-of-range or non-numeric values fall back to the default rather than erroring.

## HUD and storage

| Convar | Command | Type / unit | Default | What it does |
| --- | --- | --- | --- | --- |
| `tlib_hud_profile` | `setr` | string | *(empty — the server endpoint)* | Namespaces each player's saved HUD placement. Set it when one community runs several endpoints that should share one layout. |
| `tlib_community_id` | `setr` | string, `[A-Za-z0-9_-]` only | *(empty — falls back to `sv_projectName`)* | Prefix for tLib's KVP keys, so two servers on one machine do not share player storage. Characters outside the allowed set are stripped; a value that strips to nothing falls through to `sv_projectName`. Read by both client Lua and the server bundle. |

## Not convars

These look similar and are not convars — do not put them in `server.cfg`:

| Name | What it actually is |
| --- | --- |
| `tlib_min_version`, `tlib_module`, `tlib_modules` | `fxmanifest.lua` metadata keys on the **consuming** resource. |
| `tlib_menu_selftest`, `tlib_menu_refresh`, `tlib_menu_permissions` | Console commands. |
| `tlib_demo` *(as a command)* | Also a console command, `tlib_demo [on\|off\|convar]`, which toggles the convar above at runtime. The convar is the real setting. |
| `tmarketplace_resource_secret` | Nothing reads it. An earlier version of this page listed it as required; if the line is in your `server.cfg`, delete it. |
| `tlib_menu_request_timeout`, `tlib_menu_permission_refresh`, `tlib_menu_highlight_settle` | Unit-less near-misses for the three `_ms` convars above. Nothing reads them. |
