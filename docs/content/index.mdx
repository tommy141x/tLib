![](/assets/tLib/banner.jpg)

One NUI menu, one dialog and toast system, one themeable surface, one HUD editor, one web hub
with no port to open — and 40 Lua modules reached through a `tlib` global you never declare.

```lua title="fxmanifest.lua"
dependencies { 'tLib' }

shared_scripts {
    '@tLib/imports.lua',
}
```

```lua
exports['tLib']:ShowToast(nil, 'success', 'tLib is running', 'Installed correctly.')
```

## Three things to know first

- It detects the framework you already run and normalises what it reports — see
  [`access`](/docs/tLib/import-modules#access).
- There is no `config.lua`. Owners set convars in `server.cfg` — see
  [Convars](/docs/tLib/convars).
- A tLib restart takes its consumers' menus with it; they re-register when it returns — see
  the [lifecycle adapter](/docs/tLib/menu-consumers#shared-lifecycle-adapter-api-v1).

## Requirements

| Requirement | Detail |
| --- | --- |
| Runtime | **FiveM only.** Everything goes through a platform adapter, but FiveM is the only one implemented |
| Install | The **release** zip, not a source checkout — the release carries the built NUI page and server bundle |
| Load order | `ensure tLib` **before** any resource that depends on it |
| Framework | None. tLib detects yours; it does not replace it |
| Port | **None to open, and none bound.** The hub and every app tLib serves answer on the FiveM server port. Set `tlib_http_port` and tLib binds a second, full-capability door as well — see [Installation](/docs/tLib/installation#advanced-tlibs-own-listener) |

## Diagnostics

Off unless you set it. One line sends us the faults in **our** code — errors, warnings,
renderer crashes and slow-operation outliers — with no IP, no licence key, no server name
and no player identifiers:

```txt title="server.cfg"
set tlib_telemetry 1
```

Nothing is gated behind it. [Diagnostics](/docs/tLib/telemetry) is the full account of what
is and is not sent.
