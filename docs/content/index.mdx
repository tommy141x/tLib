![](/assets/tLib/banner.jpg)

One NUI menu, one dialog and toast system, one themeable surface, one HUD editor, one HTTP
port — and 40 Lua modules reached through a `tlib` global you never declare.

```lua title="fxmanifest.lua"
dependencies { 'tLib' }

shared_scripts {
    '@tLib/imports.lua',
}
```

```lua
exports['tLib']:ShowToast(nil, 'success', 'tLib is running', 'Installed correctly.')
```

## What it is not

- **Not a framework.** tLib answers nothing about jobs, money or inventories. It detects the
  framework you already run and normalises what it reports — see
  [`access`](/docs/tLib/import-modules#access).
- **Not configured in a file.** There is no `config.lua`. Owners set convars in `server.cfg`
  — see [Convars](/docs/tLib/convars).
- **Not invisible when it stops.** tLib owns the screen its consumers draw on, so a restart
  takes their menus with it. They re-register when it returns — see the
  [lifecycle adapter](/docs/tLib/menu-consumers#shared-lifecycle-adapter-api-v1).

## Requirements

| Requirement | Detail |
| --- | --- |
| Runtime | **FiveM only.** Everything goes through a platform adapter, but FiveM is the only one implemented |
| Install | The **release** zip, not a source checkout — the release carries the built NUI page and server bundle |
| Load order | `ensure tLib` **before** any resource that depends on it |
| Framework | None. tLib detects yours; it does not replace it |
| Port | One, `tlib_http_port`, default `7777`. Every app tLib serves is a mount on it |
