Import modules are lightweight Lua modules you reach through the `tlib` global. They load on demand — only when first accessed — so **a consumer declares nothing**.

## Setup

```lua title="fxmanifest.lua"
dependencies { 'tLib' }

shared_scripts {
    '@tLib/imports.lua',
}
```

That is the whole of it. `tlib.kvp` loads `kvp` the first time you touch it.

### Declaring modules

`tlib_modules` still works and is still accepted. It makes a load eager, which buys
you an at-boot failure for a module that does not **compile**, and it keeps the
manifest an auditable list of what the resource uses:

```lua title="fxmanifest.lua"
tlib_modules {
    'coords',
    'kvp',
}
```

Two things to know about it:

- A name tLib does **not provide** raises nothing. It is not a failed load, it is no
  load at all, and the first `tlib.<name>` is then an export proxy that throws
  `attempt to index a function value` wherever it happens to be used. Pin
  `tlib_min_version` instead; that is what reports a tLib too old to have a module.
- **Three names still matter**, and for three different reasons:
  - `tlib_module { 'realtime' }` is **required**. `server/lib/realtime/index.ts` walks
    every resource's manifest for this name and only then registers the `rt*` exports, so
    without it nothing in `tlib.realtime` has an export to call.
  - `tlib_module { 'marketplace' }` is required to register content types.
    `tlib.marketplace.registerType` otherwise gets `false` back from the bridge and warns,
    naming the line to add. The resource still starts; its types just never register.
  - `tlib_module { 'menu' }` matters when **loading the module is the wiring** — it
    defines the bare globals `MenuSchema` and `MenuCatalog`, and a consumer whose own
    shared files read those globals has no `tlib.menu` access to trigger the lazy load.

  Both spellings are accepted in every case (`tlib_module` and `tlib_modules`).

Two modules load themselves, in every consumer, with nothing declared: `occupancy`
and `telemetry`. Their wiring happens when the file loads — a net-event handler, a
NUI callback, a flush thread — so there may be no call to trigger a lazy load, and
until something loaded them they were simply off. See `AUTOLOAD` in `imports.lua`.
`telemetry` defaults to studio-authored resources only; declare it to opt in.

Then in your scripts:

```lua
local kvp = tlib.kvp
local settings = tlib.settings
```

## access

Decides who may use your resource, on the server, in a way the server owner configures.

Server owners gate things differently — an ACE, a QBox job, an item in an ox_inventory,
or a function in their own framework — so `access` makes all of those the same shape.

```lua title="config.lua"
Config.access = {
    mode = "item",          -- everyone | ace | job | item | custom

    ace  = "tdetector.use",
    job  = { police = 0, sheriff = 2 },   -- job = MINIMUM grade
    item = "radar_detector",
    count = 1,                             -- how many of `item`; default 1

    custom = function(src) return false end,
}
```

`mode` may also be a list — `mode = { "ace", "item" }` passes if **either** does.

### Server

```lua
local gate = tlib.access.gate(Config.access, { key = 'detector', label = 'the detector' })

RegisterNetEvent('tDetector:deploy', function()
    if not gate:allowed(source) then return end
    -- ...
end)
```

| Function                  | Description                                                             |
| ------------------------- | ----------------------------------------------------------------------- |
| `gate:allowed(src)`       | The decision. Call it before **every** privileged action.               |
| `gate:push(src)`          | Recompute and send the answer to that player's client mirror.           |
| `gate:invalidate(src)`    | Drop the cached answer after you change what the gate reads. `nil` = all. |
| `gate:describe()`         | One line of prose for `<resource>_diag`.                                |
| `gate:report()`           | The same thing structured — assert on this, not on the prose.           |
| `access.jobs(src)`        | `{ [job] = grade }` from the detected framework.                        |
| `access.count(src, item)` | How many of an item, from the detected inventory.                       |
| `access.framework()` / `access.inventory()` | The **name** of what was detected, or `nil` — not the adapter. |
| `access.use(fw, inv)`     | Pin detection. `'none'` for neither, `'auto'` to go back to detecting.  |
| `access.registerFramework(a)` / `registerInventory(a)` | Teach it about a fork.                     |
| `access.problems(block, label, env)` | Check a block without building a gate. See below.            |

### Checking a block yourself

`gate()` already validates the block it is given, so most resources never call this. Reach for
it when your resource has its own startup config validator and you want the access block
reported alongside everything else it checks, in one pass.

```lua
for _, problem in ipairs(tlib.access.problems(Config.access, 'the detector', false)) do
    print(problem)
end
```

The third argument is the one that matters, because it separates two problems that read alike
and are not alike:

| `environment` | Catches                                                  | When it is true                                            |
| ------------- | -------------------------------------------------------- | ----------------------------------------------------------- |
| `false`       | A mistake in the file — a misspelled mode, a `job` of the wrong shape | The moment the file is read. It can only be fixed by editing the file, and it disables the gate. |
| `true`        | `mode = 'job'` with no framework in sight                | Only once resources have settled.                            |

<Callout type="warning">
  Do not check the environmental half at startup. A framework that simply has not started yet
  is indistinguishable from one that is missing, so asserting it early prints a confident,
  wrong error on a perfectly healthy server. It never disables the gate either — the gate
  starts passing on its own the moment the framework appears.
</Callout>

### Client

The client half is for **drawing the UI only**.

```lua
local gate = tlib.access.gate({ key = 'detector' })   -- same key as the server

if gate:allowed() then showButton() end
gate:onChange(function(allowed) toggleButton(allowed) end)
gate:refresh()   -- after going on duty, picking the item up, etc.
```

<Callout type="warning">
  `gate:allowed()` on the client is a cached copy of a server decision, living in a process
  the player controls. It answers "should I draw the button?", never "may this player do the
  thing." If your net event handler does not call the **server** gate's `allowed(source)`,
  you have written a suggestion, not a gate.
</Callout>

### Fails closed, always

A framework that is absent, not yet started, or throwing answers **no jobs**, which denies.
A `custom` function that errors denies, and one returning a truthy non-boolean (`return player`)
denies too. An unset ACE denies. A gate with config errors denies everyone and says why.
Nothing here falls back to "allow" — a missing dependency is never a reason to hand out the
resource.

### Replacing the logic entirely

`custom` is the escape hatch: a plain Lua function in the owner's own config file, so a server
owner can replace the decision wholesale. `registerFramework` / `registerInventory` cover the
other case: the same gate semantics, against a core this module does not ship an adapter for.

```lua title="server/sv_access.lua"
tlib.access.registerFramework({
    name   = 'my_framework',
    detect = function() return GetResourceState('my_framework') == 'started' end,
    jobs   = function(src) return { police = 3 } end,   -- { [job] = grade }
})
```

Moving from a hand-written "return the player's job" hook: `jobs` returns a **map** of every
job to its grade, not a single job, so a player who is both police and sheriff is expressible
and so are grades. `detect` is yours too, so the framework does not have to be one that merely
happens to be running.

<Callout type="note">
  Adapters register into the **consuming resource's own server VM**, so `registerFramework`
  has to be called from a `server_script` in that resource — not from `config.lua`, which is
  shared. A resource that ships under escrow must therefore keep one server file in
  `escrow_ignore` for this, or the extension point is unreachable for the owner it exists for.
</Callout>

### Supported frameworks and inventories

Detected independently — these are separate questions answered by separate resources, so
nat2k15 for jobs alongside ox_inventory for items is a supported setup, as is an item gate
on a server with no framework at all.

| Axis | Supported, in detection order |
| --- | --- |
| Framework (`job`) | `qbx_core`, `qb-core`, `ND_Core`, `es_extended`, `ox_core`, `nat2k15framework` |
| Inventory (`item`) | `ox_inventory`, `qs-inventory`, `codem-inventory`, `origen_inventory`, `core_inventory`, `tgiann-inventory`, `qb-inventory`, `ps-inventory`, `jpr-inventory` |

Order matters: `qbx_core` is checked before `qb-core` because QBox registers the `qb-core`
export names, so the legacy path "works" there and silently returns a deprecated shim.
Detection requires the resource to be **started**, not merely present, and is redone whenever
any resource starts — so a gate built before your framework loads starts working by itself.

Grades differ by framework and `access` normalises them: qb nests (`job.grade.level`), ESX is
flat (`job.grade`), ND uses `groups[name].rank`. A framework with no grade concept reports `0`,
so `job = { LSPD = 0 }` works and `job = { LSPD = 3 }` **denies** rather than ignoring the `3`.

<Callout type="note">
  **vRP** is not in the table. vRP2 registers no exports at all — an outside resource cannot
  query it without running inside the vRP context — so there is no adapter to ship. Load a
  script into vRP with `vRP.loadScript`, then call `tlib.access.registerFramework`. Note vRP
  groups are a set with no numeric rank, so report grade `0`.
</Callout>

## config

Validates an owner-edited `config.lua` once at startup and refuses to run on a broken one.

| Function                       | Description                                                             |
| ------------------------------ | ----------------------------------------------------------------------- |
| `config.check(tbl, spec)`      | Validates, prints every problem, returns `false` if any were fatal.     |
| `config.validate(tbl, spec)`   | Same checks, returns `{ ok, errors, warnings }` and prints nothing.     |

Use `check` in a resource; use `validate` in tests, or when you want to route the
messages somewhere other than the console.

```lua
local ok = tlib.config.check(Config, {
    file = 'shared/config.lua',
    keys = {
        detectionRangeMeters = { type = 'number', default = 500.0, min = 1, max = 2000 },
        speedUnit            = { type = 'string', default = 'kmh', oneOf = { 'kmh', 'mph' } },
        enableSiren          = { type = 'boolean', default = true },
        radarResources       = { type = 'list',   default = {} },
    },
})
if not ok then return end
```

### Spec

| Field        | Description                                                                          |
| ------------ | ------------------------------------------------------------------------------------ |
| `file`       | Path shown in messages. Use the path the owner actually edits.                        |
| `keys`       | Map of key name → definition.                                                         |
| `prefix`     | Table name in messages. Defaults to `Config`.                                         |
| `allowUnknown` | Skip the unknown-key warnings. Only for a table that legitimately holds extra keys. |

A key definition takes `type` (`number`, `string`, `boolean`, `list`, `table`),
`default`, `required`, `min`, `max`, `oneOf`, and `fix` to override the suggested
remedy.

### What it guarantees

- **Every** problem is reported at once, not just the first.
- Each message names the file, the key, what was expected, what was found, and a fix.
- A default fills a key the owner **omitted**. A value the owner actually set is
  **never** silently replaced: a rejected value is reported and left alone, so what runs
  never quietly differs from what the file says.
- An unknown key warns and suggests the key that was probably meant, including the
  unit-less near-misses (`detectionRnge` → `detectionRangeMeters`) that naming units in
  keys tends to produce.
- A missing `required` key is fatal, and the resource stops at its own config.

## coords

Vehicle coordinate math helpers for transforming positions between local and world space.

| Function                                               | Description                                                     |
| ------------------------------------------------------ | --------------------------------------------------------------- |
| `Coords.localToWorld(right, fwd, up, pos, lx, ly, lz)` | Vehicle-local → world position.                                 |
| `Coords.worldToLocal(right, fwd, up, pos, wx, wy, wz)` | World → vehicle-local position.                                 |
| `Coords.buildBoneRotMatrix(rx, ry, rz)`                | Build world-space rotation matrix from bone angles (ZXY order). |
| `Coords.boneLocalToWorld(...)`                         | Bone-relative → world position.                                 |
| `Coords.worldToBoneLocal(...)`                         | World → bone-relative position.                                 |

```lua
local Coords = tlib.coords

-- Get vehicle matrix
local veh = GetVehiclePedIsIn(PlayerPedId(), false)
local right, fwd, up, pos = GetEntityMatrix(veh)

-- Convert a local offset to world position
local wx, wy, wz = Coords.localToWorld(right, fwd, up, pos, 0.5, 1.0, 0.0)
```

## demo

Reports whether the server is running in demo mode, and gives a file writer the
one line it needs to honour it.

Demo mode is a server-owner switch — the `tlib_demo` convar — that turns a server
into a self-resetting showroom. See [Convars](/docs/tLib/convars#demo-mode) for what it
is for and the warning that comes with it. This module is how your resource takes
part.

| Function                   | Side   | Description                                                                |
| -------------------------- | ------ | -------------------------------------------------------------------------- |
| `demo.active()`            | both   | `true` while demo mode is on. Cheap enough for a hot path.                  |
| `demo.dropWrite(what)`     | server | `true` when the caller must skip a write. Prints one notice per target.     |

### You probably need nothing

A resource that uses the normal primitives inherits all four of demo mode's
effects without a line of code:

- `tlib.access` gates all answer yes;
- `tlib.permission` reports every player as a superadmin;
- `tlib.fs.writeResourceFile` drops the write;
- the marketplace agent sweeps everything it installed at the next start.

### Unless you write files yourself

The exception is a resource with its **own** file writer that does not go through
`tlib.fs`. One line at the top of that function is the whole integration:

```lua title="server/sv_admin.lua"
local function saveData(json)
    if tlib.demo.dropWrite('data.json') then return true end
    return tlib.fs.writeResourceFile('data.json', json)
end
```

<Callout type="warning">
Return **success** to the caller, not a failure. Every caller of a save function
treats a failure as data loss and says so to the player — correctly, normally. On
a demo server the save did exactly what was asked of it, so failing it puts a red
error behind every settings change and teaches visitors that the demo is broken.
The console already says, once per file, what happened.
</Callout>

This only works if your resource keeps a complete in-memory mirror of its state
and treats the file as write-behind. Dropping the write then leaves the mirror
serving the session, and the next start reads the shipped file back.

### Reacting to it in your own code

Only if you have state tLib cannot see. `demo.active()` is readable on both sides;
on the client it is pushed by tLib rather than read from the convar, so it is
correct whether the owner wrote `set` or `setr`.

<Callout type="warning">
Never use `demo.active()` to decide something a player could benefit from being
wrong about on the client. It is a display and convenience signal. Demo mode's
real effects are all applied server-side, which is the only place they are
enforceable.
</Callout>

## devgate

A gate for a feature that exists on your own servers and is **absent** from the
shipped build.

| Function              | Side | Description                                                  |
| --------------------- | ---- | ------------------------------------------------------------ |
| `tlib.devgate(name)`  | both | Predicate for the convar `name`. Reads it on every call.      |

```lua title="client/cl_feature.lua"
local isInternal = tlib.devgate('my_resource_convar')

if isInternal() then
    RegisterCommand('my_internal_tool', runTool, false)
end
```

tLib supplies the mechanism and never the name. Your resource names its own
convar, which is what lets the name be encrypted: put the call in a script that
is **not** in your `escrow_ignore` and there is no string a customer can read out
of the build, so there is nothing for them to find and nothing to switch on.
Naming it in an exempt file defeats the module.

### Gate registration, not behaviour

Nothing should surface at all — no command, no keybind, no menu row, no NUI
panel, no export. A command that exists and refuses, or a row that renders
disabled, tells the customer the feature is there and earns a support question
about something they do not have.

```lua
-- WRONG: the command exists, so `cmdlist` advertises it.
RegisterCommand('my_internal_tool', function()
    if not isInternal() then return print('not available') end
    runTool()
end, false)
```

### When the switch takes effect

The convar is read on every call, never captured when the gate is made, so a
replicated convar flipped mid-session changes the answer immediately. Where the
*registration* happens once at load, off → on still needs a resource restart
while on → off takes effect at the next call. Where a surface is rebuilt per use
— a command's sub-command table, the payload sent when a panel opens — call the
predicate there and both directions are immediate.

<Callout type="warning">
A client VM only sees a convar written with `setr`. `set` is server-only, so a
client-side gate on a `set` convar is permanently off.
</Callout>

Any of `1`, `true`, `yes` and `on` turn it on, in any case. Anything else,
including an unset convar, is off: the gate hides features, so failing open would
ship them.

## diag

Console blocks for the things an operator has to go and fix — a config file that
failed to load, an escrow error, an inventory that cannot be asked a question.

You write prose. `diag` does the wrapping, the dashed rules, the `^colour` codes and
the `[resource]` prefix on every line, so a block is three lines of Lua instead of
fifteen `print` calls and every resource's blocks look alike.

| Function                       | Description                                                       |
| ------------------------------ | ----------------------------------------------------------------- |
| `Diag.fatal(title, opts)`      | Red, prefixed `FATAL:`. Nothing works until this is fixed.         |
| `Diag.error(title, opts)`      | Red. Something is denied or broken, the resource still runs.       |
| `Diag.warn(title, opts)`       | Yellow. Works, but probably not the way the operator intended.     |
| `Diag.info(title, opts)`       | White.                                                             |
| `Diag.render(level, title, o)` | The lines, without printing them — for a support dump or a panel.  |
| `Diag.wrap(text, width, ind)`  | The word wrap on its own.                                          |
| `Diag.said(key)`               | Has this `once` key already printed?                               |
| `Diag.reset()`                 | Forget every `once` key.                                           |

`opts` is `{ cause, fix, detail, scope, once }`, all optional. `fix` takes a string
or a list — one renders as `To fix:`, several as `Fix it one of these ways:`, which
matters because an operator must not think they need to do all of them. `once` is a
key: the first call with it prints, the rest are dropped. `scope` overrides the
resource name in the prefix.

```lua
tlib.diag.fatal('Config does not exist. tRadio cannot start.', {
    cause = 'config/config.lua failed to load. Almost always a Lua syntax error in your edited copy.',
    fix   = 'Scroll UP in this console: FiveM printed the exact file and line just before this message.',
    once  = 'no-config',
})
```

It prints; it never logs. There is no level to configure and nothing to route, so a
block always reaches the console the operator is looking at.

<Callout type="info">
  Put these blocks in files your customers receive on every update, not in
  `escrow_ignore`'d config files. The partial upload that breaks a config file is
  usually the one that takes the explanation with it.
</Callout>

## kvp

Typed KVP wrapper with automatic community-server prefixing. Each server gets isolated storage via `tlib_community_id` or `sv_projectName`. `tlib_community_id` needs `setr` — it is read on both sides; see [Convars](/docs/tLib/convars).

### Typed Getters / Setters

| Function                      | Description               |
| ----------------------------- | ------------------------- |
| `kvp.getString(key, default)` | Get a string value.       |
| `kvp.getFloat(key, default)`  | Get a float value.        |
| `kvp.getInt(key, default)`    | Get an integer value.     |
| `kvp.getBool(key, default)`   | Get a boolean value.      |
| `kvp.getJson(key, default)`   | Get a JSON-decoded value. |
| `kvp.setString(key, value)`   | Set a string value.       |
| `kvp.setFloat(key, value)`    | Set a float value.        |
| `kvp.setInt(key, value)`      | Set an integer value.     |
| `kvp.setBool(key, value)`     | Set a boolean value.      |
| `kvp.setJson(key, value)`     | Set a JSON-encoded value. |

### Auto-Detect

| Function                | Description                |
| ----------------------- | -------------------------- |
| `kvp.get(key, default)` | Auto-detect type on read.  |
| `kvp.set(key, value)`   | Auto-detect type on write. |

### Utilities

| Function          | Description                           |
| ----------------- | ------------------------------------- |
| `kvp.has(key)`    | Returns `true` if the key exists.     |
| `kvp.delete(key)` | Delete a key.                         |
| `kvp.key(key)`    | Returns the full prefixed key string. |

```lua
local kvp = tlib.kvp

kvp.setString('callsign', '1-Adam-12')
local callsign = kvp.getString('callsign', 'Unknown')

kvp.setJson('loadout', { primary = 'rifle', secondary = 'pistol' })
local loadout = kvp.getJson('loadout', {})
```

## settings

Typed settings store backed by KVP. Supports default values, user-set tracking, and server-pushed defaults.

| Function                     | Description                                                        |
| ---------------------------- | ------------------------------------------------------------------ |
| `settings.create(defs)`      | Create a store from a definition array `{ key, type, default }[]`. |
| `store:get(key)`             | Get a setting value.                                               |
| `store:set(key, value)`      | Set a setting value (persisted to KVP).                            |
| `store:isUserSet(key)`       | `true` if the player explicitly set this value.                    |
| `store:applyDefaults(table)` | Apply server defaults only to keys the player hasn't set.          |
| `store:reset(key)`           | Reset to default and remove from KVP.                              |

```lua
local settings = tlib.settings

local store = settings.create({
    { key = 'volume', type = 'float', default = 0.8 },
    { key = 'darkMode', type = 'bool', default = false },
    { key = 'language', type = 'string', default = 'en' },
})

local vol = store:get('volume')    -- 0.8 (default)
store:set('volume', 0.5)           -- Persisted to KVP
store:isUserSet('volume')          -- true
store:reset('volume')              -- Back to 0.8
```

## modules

Server-side content discovery. A **module** is a self-contained folder plus a
`module.json` that declares what it is.

```
layouts/QRX-720/module.json        { "kind": "layout", "id": "QRX-720", … }
layouts/themes/dark/module.json    { "kind": "theme",  "id": "dark",    … }
```

<Callout type="warning" title="This module discovers layout and theme, never sound">
  On a FiveM resource a sound is a flat audio file — `layouts/sounds/ptt.wav` — so an
  operator can drop a `.wav` in with no manifest to author. Asking this module to scan for
  sounds **throws**, and a `sound` manifest that reaches a resource's `layouts/` is refused
  by name. Sounds carry a `module.json` only on the marketplace, where the installer reads
  it and writes out just the audio.
</Callout>

| Function                                                     | Description                                                          |
| ------------------------------------------------------------ | -------------------------------------------------------------------- |
| `modules.scan(basePath, kind, resourceName?)`                | The ids of every usable module of `kind`, sorted.                    |
| `modules.list(basePath, kind, resourceName?)`                | The same, as `{ id, manifest }` so you need not re-read the manifest. |
| `modules.read(basePath, id, kind?, resourceName?)`           | One module's validated manifest, or `nil, err`.                      |
| `modules.load(basePath, id, fileName, resourceName?)`        | Read a file out of a module folder.                                  |
| `modules.hasFile(basePath, id, fileName, resourceName?)`     | Whether a module ships an optional asset.                            |
| `modules.validate(raw, id, kind?)`                           | Validate a decoded manifest directly.                                |
| `modules.clearCache()`                                       | Clear the scan cache, for modules added at runtime.                  |
| `modules.onRefusal(basePath, id, err)`                       | Replace with your logger; called for every folder refused.           |

```lua
local modules = tlib.modules

-- Point refusals at your own log before the first scan.
modules.onRefusal = function(base, id, err)
    log(('skipped %s/%s — %s'):format(base, id, err), tlib.logger.WARN)
end

for _, entry in ipairs(modules.list('layouts', 'layout')) do
    print(entry.id, entry.manifest.name, entry.manifest.version)
end

local html = modules.load('layouts', 'QRX-720', 'ui.html')
local hasDark = modules.hasFile('layouts', 'QRX-720', 'radio-dark.png')
```

### The manifest

`schema`, `kind`, `id`, `name` and `version` are required; `author`, `license`,
`description` and `slug` are optional. A `sound` module — a marketplace artefact,
never read off a resource — also carries `sound.file`, and may carry
`sound.durationSeconds`, `sound.toneKeys` and `sound.peaks`.

Three rules are worth knowing before you author one by hand:

- **`id` must equal the folder name, byte for byte.** This is what catches a
  folder renamed on copy, including a case-only rename on a case-sensitive
  filesystem.
- **`kind` is declared, never inferred from location.** Keep the category
  directories for humans; tooling branches on `kind`. A folder whose `kind`
  does not match the directory it sits in is **refused** at start, naming the
  folder, rather than loaded and then 404ing on `ui.html` on a player's machine.
- **`sounds` and `themes` are reserved** and cannot be module ids. They are the
  category directories inside `layouts/` — `sounds` included, because it still
  holds the flat audio files and a layout called `sounds` would shadow every one
  of them.

A module declares its **identity**; its **content** is found by a live directory
scan, so a folder dropped in while the resource is running is discovered without
a restart. A manifest lists no files, and `clearCache()` is what makes a new
folder visible to a scan that has already run.

## logger

Levelled console logging with the same line format in every resource: `[scope][LEVEL] message`.

| Function / field                     | Description                                                     |
| ------------------------------------ | --------------------------------------------------------------- |
| `logger.create(scope)`               | Return a `log(...)` function that prefixes every line.          |
| `log(...)`                           | Log the arguments, space-joined. Defaults to `INFO`.            |
| `log(..., level)`                    | A **trailing number** is taken as the level, not printed.       |
| `logger.DEBUG` / `INFO` / `WARN` / `ERROR` | `1` / `2` / `3` / `4`. Higher is more severe.             |
| `logger.setLevel(level)`             | Minimum level printed (default `INFO`).                         |

```lua
local log = tlib.logger.create('tRadar')

log('layout loaded:', name)              -- [tRadar][INFO] layout loaded: ...
log('no layout, falling back', tlib.logger.WARN)
log('state dump', tlib.logger.DEBUG)     -- hidden unless setLevel(DEBUG)
```

<Callout type="warning">
  A trailing number is consumed as the level: `log('count', 4)` logs `count` at `ERROR`. Pass
  numbers you mean to print as strings, or anywhere but last.
</Callout>

## permission

Admin and permission checks that match tLib's own rules. Both sides, with different
interfaces: the server answers *about a player*, the client answers *about this player*.

### Server

| Function                     | Description                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `permission.isAdmin(src)`    | `true` for `tlib.admin` or `tlib.superadmin`. Same answer as `exports.tLib:IsPlayerAdmin`. |
| `permission.level(src)`      | `0` none, `1` admin, `2` superadmin.                                                 |
| `permission.has(src, key)`   | Any permission key, resolved by tLib — ACE, or a framework resolver registered with tLib. |
| `permission.hasBatch(src, keys)` | A whole key list in one round trip. Returns `{ [key] = boolean }`.               |
| `permission.hasAll(src, keys)` | `true` only if every key is held. One round trip. An empty list is `true`.         |

```lua
RegisterNetEvent('myres:saveDefaults', function(data)
    local src = source
    if not tlib.permission.isAdmin(src) then return end
    -- ...
end)

if tlib.permission.has(src, Config.acePermission) then
    -- open the panel
end
```

<Callout type="warning">
  **In demo mode `level(src)` returns `2` for everybody**, so `isAdmin(src)` is true for
  everybody — see [`tlib_demo`](/docs/tLib/convars#demo-mode). `has(src, key)` is not
  affected. Never set that convar on a server whose data you care about.
</Callout>

`isAdmin` is answered inside your resource, so it works even while tLib is still starting. `has`
has to ask tLib, because a registered resolver lives there. If tLib can't answer, it returns
`false` rather than falling back to a plain ACE check, since a resolver is allowed to deny what
ACE would grant.

### Client

| Function                      | Description                                                        |
| ----------------------------- | ------------------------------------------------------------------ |
| `permission.isAdmin()`        | `true` for this player, as last answered by the server.            |
| `permission.level()`          | `0` none, `1` admin, `2` superadmin.                               |
| `permission.onChange(fn)`     | `fn(isAdmin, level)` on every change, and once immediately.        |
| `permission.refresh()`        | Ask the server for a fresh answer.                                 |

```lua
local hudIsAdmin = false

tlib.permission.onChange(function(isAdmin)
    hudIsAdmin = isAdmin
end)
```

Use `onChange` rather than reading `exports['tLib']:IsAdmin()` once at resource start. That
export is a value tLib's client caches when **tLib** starts; revoke an ace on a running server
and a panel built from it keeps drawing the admin section until the player reconnects.

<Callout type="warning">
  This is a cached copy of a decision the server made, in a process the player controls. It
  answers "should I draw the admin tab?" and never "may this player do the thing". Every
  privileged net event still has to re-resolve the ace server-side.
</Callout>

## net

A net event with its guard built into the registration rather than written at the top of the
handler.

### Client — `net.fromServer`

A server-triggered net event reaches the client with `source == 65535`; a local `TriggerEvent`
from another resource or a cheat menu does not. `fromServer` runs your handler only for the
former.

```lua
tlib.net.fromServer('myres:serverDefaults', function(defaults)
    applyServerDefaults(defaults)
end)
```

A rejected event is dropped and reported in the console **once per event name** — the first
rejection says everything the hundredth would, and a per-call line would hand an attacker a
console flood. Registering two handlers for one name is fine: both run, as FiveM intends.

### Server — `net.fromClient`

The source guard, a rate limit and an optional permission gate, applied once.

```lua
tlib.net.fromClient('myres:requestSettings', function(src)
    TriggerClientEvent('myres:settings', src, buildSettings(src))
end)

local gate = tlib.access.gate(Config.access, { key = 'myres' })

tlib.net.fromClient('myres:saveLayout', {
    allow    = function(src) return gate:allowed(src) end,
    onDenied = function(src) TriggerClientEvent('myres:denied', src) end,
}, function(src, layout)
    saveLayout(src, layout)
end)
```

| Option      | Default | Description                                                               |
| ----------- | ------- | ------------------------------------------------------------------------- |
| `rateLimit` | `1000`  | Minimum ms between one player's calls. `0` disables it.                   |
| `allow`     | *none*  | `fn(src) -> boolean`. Only `true` is a grant. Throwing denies.            |
| `onDenied`  | *none*  | `fn(src)`, so you can tell the player.                                    |

The handler is called as `fn(src, ...)`. A rate-limited call is dropped **silently**, so a
feature that has to reopen a panel it just closed must not go back through the request path —
use `panel:reopen()` from [opengate](#opengate). A denial by `allow` calls `onDenied` and
prints once per event name.

<Callout type="warning">
  Without `allow`, `fromClient` is a source guard and a rate limit — **not** a permission gate.
  That is correct for a request-shaped event any player may fire. Pass `allow` to make it a gate,
  and put a `tlib.access` gate in it rather than inventing a second mechanism.
</Callout>

## opengate

The "may I open my panel?" handshake: the client asks, the server decides fresh on every open,
and the answer is one of three things.

### Server

```lua
local gate = tlib.access.gate(Config.access, { key = 'myres' })

tlib.opengate.serve({
    key      = 'settings',
    allow    = function(src) return gate:allowed(src) end,
    configOk = function() return myresConfigOk() end,
    payload  = function(src) return { isAdmin = tlib.permission.isAdmin(src) } end,
})
```

| Option      | Default | Description                                                                 |
| ----------- | ------- | --------------------------------------------------------------------------- |
| `key`       | `settings` | Namespaces the wire events. Must match the client's.                     |
| `allow`     | **required** | `fn(src) -> boolean`. A missing one denies everyone and says so at boot. |
| `configOk`  | *none*  | `fn() -> boolean`. Omit it if the resource has no config spec to check.      |
| `payload`   | *none*  | `fn(src) -> table`. Travels with the reply. Draw hints only.                |
| `rateLimit` | `1000`  | Passed through to `net.fromClient`.                                         |

The checks run in this order, and the order matters: rate limit, then `configOk`, then `allow`.
A broken config is not a permissions problem, and answering "you are not allowed" to a player on
a misconfigured server sends them to the wrong person.

A panel that really is open to everyone writes `allow = function() return true end`. There is
no default: an omitted `allow` denies everyone rather than opening the panel.

### Client

```lua
local panel = tlib.opengate.panel({
    key      = 'settings',
    onOpen   = function(data) openSettingsDialog(data) end,
    onDenied = function() toast("You don't have permission to use this.") end,
    onBroken = function() toast("This server's config has errors — ask an admin to check the console.") end,
})

RegisterCommand('myres', function() panel:open() end, false)
```

| Member          | Description                                                                 |
| --------------- | --------------------------------------------------------------------------- |
| `panel:open()`  | Ask the server. The answer arrives as one of the three callbacks.           |
| `panel:reopen()` | Re-run `onOpen` with the last answer. No round trip. Returns `false` if there was never one. |
| `onOpen`        | **required.** `fn(payload)`.                                                |
| `onDenied`      | **required.** A denial the player is never told about reads as a bug.       |
| `onBroken`      | Optional, but omitting it means a broken-config reply tells the player nothing. |

All three replies are registered through `net.fromServer`, so a local `TriggerEvent` can neither
open the panel nor fake a denial.

<Callout type="warning">
  `reopen()` exists for one case: a feature that had to close the panel to use the game view — a
  3D prop editor, a world placement — and has to put the player back. The request path is
  rate-limited on the server and drops the extra call silently, so an admin who opened the editor
  and cancelled straight away would get nothing back. `reopen()` replays the grant the server
  already gave; it cannot create one, and with no previous open it does nothing.
</Callout>

#### Keybinds

```lua
})
```

Defaults: `group` is `keyboard`, `pair` is `true`, `default` is `''` (which appends

<Callout type="warning">
  **The command token IS the stored binding.** FiveM persists a player's rebind against
  the token, so renaming one silently discards every player's rebind with no error and no

</Callout>

## occupancy

One shared answer to who is aboard a vehicle, in which tier, and which of them may act on
it. **The controller is the driver if a driver is seated, otherwise the front passenger.**

This module is in `AUTOLOAD` — it loads itself into every consumer, because on the server
its file scope registers the handlers that keep the cache honest and a consumer may have no
Lua call that would ever trigger a lazy load.

### Client

| Function | Description |
| --- | --- |
| `occupancy.poll()` / `.state()` | A copy of `{ seat, vehicle, netId, driver, passenger, partner, isController, tier, cabinSeat, cabinVehicle, cabinNetId }`. |
| `occupancy.isController()` | May this client act on the vehicle? |
| `occupancy.isFrontSeat()` / `.isDriver()` / `.isPassenger()` / `.isRearPassenger()` / `.isAboard()` | Predicates about **this** player — no arguments. |
| `occupancy.tier()` | `driver` \| `passenger` \| `rear` \| `nil`. |
| `occupancy.myVehicle()` | `handle, netId` — `nil` unless in a **front** seat. |
| `occupancy.cabin()` | `handle, netId, seat, tier` — any seat, so `nil` only on foot. |
| `occupancy.partner()` | The other front seat's server id. |
| `occupancy.onChange(fn)` | `fn(state)`. Returns an unsubscribe function. |
| `occupancy.startReporting()` / `.startSweep(ms)` / `.stopSweep()` | Opt in to the move ping and the poll loop. Sweep default `250`. |

### Server

| Function | Description |
| --- | --- |
| `occupancy.isControllerOf(src, netId)` / `.isFrontSeat(src, netId)` / `.isAboard(src, netId)` | **Gates.** Each re-reads the host; none can be stale. |
| `occupancy.refresh(src)` / `.refreshOccupant(src)` | Re-read and repair the cache. `seat, netId[, tier]`. |
| `occupancy.seatOf(src)` / `.occupantSeatOf(src)` / `.tierOf(src)` | The cache. |
| `occupancy.frontSeats(netId)` / `.occupantsOf(netId)` / `.controllerOf(netId)` | By vehicle. Copies. |
| `occupancy.partnerOf(src)` / `.peersOf(src)` | The other front seat / everyone aboard. |
| `occupancy.onChange(fn)` / `.onCabinChange(fn)` | Front-seat edges / every-seat edges. Both return an unsubscribe. |
| `occupancy.seatTier(seat)` / `.clear(src)` / `.startSweep(ms)` / `.stopSweep()` | Helpers. Sweep default `1000`. |

<Callout type="warning">
  **Gate on the predicates, read the cache for display.** `isControllerOf`, `isFrontSeat`
  and `isAboard` re-read the host on every call — and `isControllerOf` re-reads the driver
  again before granting to a passenger. `occupantsOf` / `tierOf` / `occupantSeatOf` are a
  cache repaired by a rate-limited client ping and can briefly name a seat the player has
  left. That can never grant control, because control is never read from the cache.
</Callout>

**The front-seat and the cabin fields answer different questions.** `seat`, `vehicle`,
`netId`, `partner` and `isController` are front-seat-only and are `nil` for a rear
passenger — so `state.seat ~= nil` reads as "may I operate this". A rear passenger shows up
only in `tier`, `cabinSeat`, `cabinVehicle` and `cabinNetId`, and only `onCabinChange` fires
for them; `onChange` does not.

`tlib:occupancy:moved` is one event name for every resource — each consumer VM keeps its own
cache over the same natives, and one client ping repairs all of them at once. Treat its
payload as a hint: the seat is re-read from the host, so a lying client gets the truth
written down instead.

Neither sweep runs until you start it.

## jsonstore

The single memoised writer for one resource's JSON data file, with per-owner schema seeding,
versioning and forward migration.

| Function | Description |
| --- | --- |
| `jsonstore.open(opts)` | The store. `opts.log` is **required**. |
| `store:read()` / `store:section(name)` | The whole document, or one section. `{}` when absent. |
| `store:write(sections)` | Merge and persist. `false` when nothing reached the disk. |
| `store:ensure(schema)` | Seed or migrate this owner's slice. Returns what it did. |
| `store:schemaState(owner)` | That result again, or `nil`. |
| `store:locked()` | Why writes are refused, or `nil`. |

`opts` defaults: `file` to `data.json`, `resource` to `GetCurrentResourceName()`.

```lua
local store = tlib.jsonstore.open({ log = tlib.logger.create('tDetector') })

store:section('props')            -- the section, or an empty table
store:write({ props = placements })
```

**`open` is memoised per resource and file** — the same pair hands back the *same* object,
so you cannot accidentally create a second writer by calling it twice.

<Callout type="warning">
  **A lock is permanent for the session, and it fails closed.** An unparseable file, a
  malformed `__schema`, a version downgrade, a migration that throws or deletes an
  unnamed key, a failed backup or a failed write all lock the store, and every later
  `write` returns `false`. The reason is logged once; `store:locked()` is how you ask.
</Callout>

A migration that drops a top-level key it did not list in `allowRemove` is refused and
nothing is written. Write a rename as a copy plus an `allowRemove`. A malformed *schema*
raises rather than locking, so you find it on your own machine.

<Callout type="warning">
  **Migrations must be idempotent.** A `write` can report success without the bytes
  landing — demo mode drops it, and a bridge can report success too — so the store
  re-probes, and if its stamp did not land it switches to an in-memory mirror and warns.
  The next start then migrates again.
</Callout>

`__schema` is keyed by **owner**, since one document can be co-owned by several resources.
Never stamp a version when applying defaults — a document that already carries your version
is one your migrations will skip.

## fs

One function: write a file into a resource, and say so honestly when it could not.

| Function | Description |
| --- | --- |
| `fs.writeResourceFile(relPath, contents, resource, log)` | `true`, or `false, err`. `err` is never empty. |

```lua
local ok, err = tlib.fs.writeResourceFile('data.json', encoded)
```

## assets

Reconciles a stored list of operator-dropped files against what is actually in the folder.

| Function | Description |
| --- | --- |
| `assets.scan(subdir, opts)` | Sorted filenames, or `nil, reason`. |
| `assets.reconcile(tracked, diskFiles, opts)` | `list, changed`. Pure. |
| `assets.sync(tracked, subdir, opts)` | Both at once: `list, changed, reason`. |
| `assets.slug(filename)` | The name with its final extension stripped. |
| `assets.AUDIO` | `{ "wav", "ogg", "mp3" }`. |

```lua
local files, reason = tlib.assets.scan('layouts/sounds', { extensions = tlib.assets.AUDIO })
local list, changed = tlib.assets.reconcile(installedSounds, files)

-- or both at once, which refuses to prune when the folder cannot be read:
local list, changed, reason = tlib.assets.sync(installedSounds, 'layouts/sounds',
                                               { extensions = tlib.assets.AUDIO })
```

<Callout type="warning">
  **`nil` and `{}` from `scan` mean different things, and conflating them deletes data.**
  `nil` is "I could not look"; `{}` is "the folder is empty". `reconcile` prunes anything
  the list does not confirm, so handing it a failed scan wipes the registry. Use `sync`,
  which refuses to prune on a scan failure and hands back the `reason`.
</Callout>

`changed` reports **membership**, not length, so a one-in-one-out swap reports `true`.
Retained records come back byte-identical and in order — any field you added to a record,
such as a label, survives; only genuinely new files get a fresh one.

`scan` needs tLib's Node bundle (`ScanResourceFiles`); a missing export reads back as
`"unavailable"` rather than throwing.

## audio3d

Positional device audio: the server decides who is near enough to hear a vehicle-mounted
device, the client resolves each emitter's live position locally and pushes one batched
frame per tick into the consumer's own NUI.

### Server — the bus

```lua
local bus = tlib.audio3d.createBus({
    event  = 'tradar:worldSound',
    range  = Config.audioRange,
    fields = { kind = { type = 'string', max = 16 } },
})
RegisterNetEvent('tradar:emitWorldSound', function(payload)
    bus:emit(source, payload)
end)
```

| Member | Description |
| --- | --- |
| `bus:emit(src, payload)` | Receivers reached. **`0` for every rejection** — on foot, throttled, malformed, nobody near. |
| `bus:sanitize(payload)` | The whitelisted fields, or `nil` if any present field is malformed. |
| `bus:receivers(netId, sender)` | `serverIds, coords`. |
| `bus:setRange(r)` / `bus:getRange()` | Metres, clamped to `MAX_RANGE` (250). |
| `bus:stats()` | `{ sent, delivered, throttled, rejected, notAboard, capped }`. |
| `bus:forget(netId)` | Drop a vehicle's throttle state. |

`createBus` asserts `event` and `range`. Defaults: `maxReceivers` 24 (1–128),
`minIntervalMs` 100 (0–10000), `maxPerSecond` 20 (1–120).

The emitter is the **vehicle**, resolved through `occupancy.refreshOccupant(src)`, so a
sender on foot emits nothing at all.

### Client — the receiver

| Member | Description |
| --- | --- |
| `audio3d.createReceiver(opts)` | Asserts `event`, `send` and `range`. `prefix` defaults to `audio3d`, `keepAliveMs` to `6000`. |
| `rx:setLocal(netId)` | Mark the unit this player's own UI already sounds. `nil` on leaving. |
| `rx:accept(payload)` | `true` only when the frame was forwarded to the NUI. |
| `rx:pushFrame()` | How long to wait next: `250` idle, else `16`/`33`/`50` by listener speed. |
| `rx:activeEmitters()` / `rx:getLocal()` / `rx:stats()` | State. |
| `rx:setRange(r)` / `rx:stopAll()` | Range, and a full teardown. |

<Callout type="warning">
  **`send` receives ONE table that already carries `action`** — not `(action, data)`.
  Passing a `sendHud(action, data)` straight in builds `{ action = <table> }`, which
  tLib's NUI dispatcher drops silently, so the feature looks unwired rather than broken.
  Bridge it:

```lua
local function sendWorldAudio(msg) sendHud(msg.action, msg) end
```
</Callout>

A frame is dropped twice over: the bus excludes the sender, and the receiver rejects the id
you marked with `setLocal`. Mark it, or the player hears two copies of the same tone and
they comb-filter.

  **Poll it; do not use `AddStateBagChangeHandler`.** Two of the three conditions for a
  frame being current — that the consumer still names this vehicle, and that it has not
  gone stale — produce no statebag event at all, so a change handler latches onto whatever
  it last heard and never lets go.
</Callout>

Three field names are reserved in your payload: the relay writes `seq` and `netId`, and
reads `powered`. Do not use those names for anything else. A device reporting
`powered = false` publishes nothing at all.

A statebag is not withdrawn when its writer disconnects, and a write only lands while the
writer owns the entity, so `staleMs` is what clears a crashed driver's last frame.

`publishTick` reads `occupancy.isController()` live, so the occupancy sweep has to be
running or nothing is ever published.

## drivenprop

Drives an unattached, frozen prop's world matrix from its parent vehicle's each frame.

Reach for it when a prop needs a non-unit scale: scale lives in the basis-vector lengths of
`SetEntityMatrix`, and `AttachEntityToEntity` does not carry it, so a scaled prop cannot be
attached at all.

| Function | Description |
| --- | --- |
| `drivenprop.create(opts)` | A driver. `opts.onError` defaults to a print. |
| `driver.add(prop, parent, placement)` / `.update(prop, placement)` / `.remove(prop)` | Membership. |
| `driver.tick()` | `written, skipped`. |
| `driver.write(prop)` / `.isDriven(prop)` / `.count()` / `.clear()` | The rest. |
| `drivenprop.normaliseScale(v)` / `.isUnitScale(v)` | Clamped to `[0.1, 10.0]`; anything unusable lands on `1.0`. |
| `drivenprop.transform(basis, placement)` / `.localRotation(rx, ry, rz)` / `.toWorld(basis, L)` | The pure maths. |
| `drivenprop.handedness(f, r, u)` / `.assertHandedness(...)` / `.dot` / `.cross` | Basis checks. |
| `drivenprop.hasMoved(last, basis)` | Whether a rewrite is needed. |

`add` **detaches, freezes and disables collision** on the prop, and writes the matrix
before it returns. Undo any of the three and you get a specific failure: attached loses the
scale, unfrozen falls through the world, collision-enabled bounces off the vehicle.

`remove` and `clear` neither delete the prop nor re-attach it. Re-attaching it yourself
discards the scale.

<Callout type="warning">
  `transform` asserts handedness and will raise on a left-handed basis — a mesh rendered
  inside-out looks identical in every number you can print, so this is the only warning you
  get. It also returns the native's `(forward, right, up, at)` ordering, not the
  `(right, forward, up)` the rest of the module takes.
</Callout>

`create` starts a per-frame thread and an `onResourceStop` handler; merely importing the
module does not. Share one driver per resource — `vehicleprop` exposes its own as
`instance.editor.driver`.

## lifecycle

Keeps a registration against a **dependency** alive across that dependency's restarts. The
complete worked example is in [Menu Consumers](/docs/tLib/menu-consumers#shared-lifecycle-adapter-api-v1);
this is the reference.

| Member | Description |
| --- | --- |
| `lifecycle.version` | `1`. Assert it. |
| `lifecycle.watch({ resource, install, cleanup?, readyEvent? })` | The handle below. |
| `handle.ready()` / `.retry()` / `.invalidate()` / `.dispose()` | Lifecycle. `dispose` is idempotent. |
| `ctx.once(name, fn)` / `ctx.isActive()` | Inside `install`. |

## healthcheck

Ordered HTTP GET probes against a base URL, with retries, delivering one aggregate result.

| Member | Description |
| --- | --- |
| `tlib.healthcheck(opts)` / `.check(opts)` | The same call. Returns **nothing**. |

Everything arrives at `opts.callback` as
`{ success, steps, attempts, failedStep, message, url }`, where each step is
`{ name, passed, status, error }`.

Defaults: one step (`reachable`, path `/`), `retries` 2 (so three attempts), `retryDelay`
1000, `timeout` 8000, `delay` 500. A step's `path` defaults to `/` and, with no `expect`,
passes on any status from 200 to 599.

Give it either `opts.url` or `opts.waitEvent`; `waitEvent` wins, and takes the URL from the
event payload. With neither it registers nothing and does nothing.

The sequence short-circuits, so `result.steps` is shorter than `opts.steps` on a failure and
a retry re-runs from step 1. A timeout is reported as `status = 0` rather than as an error.
`%port%` in a step's `errorMsg` is substituted with the port parsed from the URL — 443 for
`https://`, 80 for `http://`, and a literal `?` for neither.

## ratelimit

A per-player minimum interval on a net event, as a closure you call at the top of the
handler.

| Function | Description |
| --- | --- |
| `ratelimit.bucket(name, intervalMs)` | Returns `fn(src) -> boolean`. **`true` means refused.** |
| `ratelimit.forget(src)` | Drop one player's timestamps. `nil` drops every player. |
| `ratelimit.reset()` | Drop the buckets themselves. Tests only. |

```lua
local gate = tlib.ratelimit.bucket('requestVehicleProps', 1000)

RegisterNetEvent('tdet:requestVehicleProps', function()
    local src = source
    if not src or src <= 0 then return end
    if gate(src) then return end
    -- ...
end)
```

<Callout type="warning">
  **The return is inverted from the obvious reading.** `gate(src)` answers "was this
  refused?", so the guard is `if gate(src) then return end`. Writing `if not gate(src)
  then return end` disables the handler rather than the rate limit.
</Callout>

`gate(nil)` answers `false` — allowed — so a missing source is not silently a denial.
Buckets are named inside your own VM, so a name can neither collide with another resource's
nor be shared with one. Asking for the same name twice hands back two closures over **one**
timestamp table, and the last `intervalMs` wins. Disconnected players are swept for you.

`tlib.net.fromClient` already applies one of these. Use `ratelimit` directly for something
that is not a net event, or to put several events on one budget.

## inference

Announce a model runtime this resource started, and find one another resource already has
up for the same weights. The exports underneath are in
[Exports](/docs/tLib/exports#local-inference); to *start* the engine, see
[Child processes](/docs/tLib/exports#child-processes).

<Callout type="warning">
  Colon-called, like `realtime`: `tlib.inference:lookup(...)`.
</Callout>

| Function | Description |
| --- | --- |
| `inference:advertise(descriptor)` | A handle, or `nil` if the advertisement was rejected. |
| `inference:lookup(capability, workload)` | Another resource's advertisement, or `nil`. Never your own. |
| `inference:withdraw(handle)` | Drop one of yours. Stopping the resource does this anyway. |
| `inference:list()` | Everything registered, for diagnostics. |

```lua
local shared = tlib.inference:lookup('text', 'qwen3-1.7b-q4_k_m')
if shared then
    -- someone else already has these weights loaded; talk to shared.url
else
    local handle = tlib.inference:advertise({
        capability = 'text',
        workload   = 'qwen3-1.7b-q4_k_m',
        url        = 'http://127.0.0.1:18291/v1',
        model      = 'local',
    })
end
```

<Callout type="warning">
  **The field is `url`, and a rejected advertisement is silent.** `advertise` returns `nil`
  with no error and no log line, so a misspelled field, a missing one and a non-loopback
  URL are indistinguishable. Check the return.
</Callout>

Give `url` as the **full** URL including the route — a looked-up engine is called at
exactly what you advertised, with nothing appended. Only `127.0.0.1`, `[::1]` and
`localhost` are accepted.

Re-advertising replaces every entry for the same resource **and capability**, so moving an
engine to a new port needs no `withdraw` first.

## telemetry

<Callout type="note">

## screentarget

Picks the **one** vehicle whose device screen this client renders.

`AddReplaceTexture` is keyed on the texture name, so it is global to the archetype and two
vehicles cannot show different screens at once. This picks the winner: your own vehicle
always, otherwise the nearest in range, with hysteresis so a passing car does not steal the
screen.

| Member | Description |
| --- | --- |
| `screentarget.create(opts)` | An arbiter. `opts.hasScreen` is required. |
| `self.update()` | `vehicle, netId, source` — or a single `nil` when nothing qualifies. |
| `self.current()` | The same, without re-deciding. |
| `self.currentDistance()` | Distance at the last `update`; `0` for your own vehicle. |
| `self.onChange(fn)` | `fn(vehicle, netId, source)`. Returns an **unsubscribe** function. |
| `self.reset()` | Forget the incumbent. |
| `self.settings()` | `{ range, switchMargin, dwellMs }`. |

Defaults: `range` 8.0 m, `switchMargin` 2.0 m (absolute metres, not a fraction), `dwellMs`
1500. `source` is `own` or `nearest`.

`onChange` fires only when the vehicle or the source changes, never on distance alone, so
it is safe to rebuild a browser inside it. Treat `update()` returning `nil` as the signal to
tear that browser down — leave it up and it paints stale pixels onto a vehicle the player
has driven away from.

`dwellMs` delays *displacement* only. Losing the incumbent takes effect at once.

## propeditor and vehicleprop

The in-vehicle prop stack. `vehicleprop` owns the model registry, the placement store and
the attach/detach lifecycle; `propeditor` owns the orbit camera and the editing UI. Create
`vehicleprop` and reach the editor through `instance.editor`.

```lua
local prop = tlib.vehicleprop.create({
    prefix = 'tdet', model = 'prop_cs_police_torch', decor = 'tdet_prop',
    saveEvent = 'tdet:savePlacement', removeEvent = 'tdet:removePlacement',
})
```

| Member | Description |
| --- | --- |
| `instance.setRegistry(cfg)` / `.isRegisteredModel(n)` / `.resolveModel(n)` / `.defaultModel()` | The model registry. |
| `instance.getPlacement(veh)` / `.setPlacements(src)` / `.getAttached(veh)` / `.detach(veh)` | Placements and props. |
| `instance.reconcile()` / `.tick()` / `.reclaimOrphans()` / `.cleanupAll()` | Lifecycle, exposed so a suite can drive it without a thread. |
| `instance.editor` | The `propeditor` instance, including `editor.driver`. |
| `propeditor.create(descriptor)` | The editor on its own, if you are not using `vehicleprop`. |
| `propeditor.orbit.*` | The camera maths — `new`, `eye`, `lookFrom`, `applyDrag`, `zoom`, `command`. |
| `vehicleprop.normaliseModelName(m)` / `.buildRegistry(builtin, cfg)` | Pure helpers. |

`create` asserts `prefix`, `model`, `decor`, `saveEvent` and `removeEvent`.

<Callout type="warning">
  **`create` is not a constructor you can call twice.** One call registers 13 NUI callbacks,
  two render threads, a decor type, a 2.5-second lifecycle thread and `playerSpawned` /
  `onResourceStop` handlers. Create one per resource, at load, and share
  `instance.editor.driver` rather than making a second driven-prop driver.
</Callout>

Three behaviours are worth knowing before using either:

- **Scale decides the attach mechanism.** A unit scale attaches with
  `AttachEntityToEntity`; anything else is driven per frame through
  [`drivenprop`](#drivenprop). So never test "is this attached" to decide whether a prop is
  live — every scaled prop answers no. Ask the tracking table.
- **`CreateObject` signals failure with `0`, which Lua treats as true.** `if not prop then`
  never catches it, and the prop simply never appears.
- **The placement, attached and model tables are emptied in place, never replaced.**
  Consumers alias them, so table identity is part of the contract.

A record the editor did not change round-trips byte-identical — it never writes a resolved
model name back, so a legacy placement is not silently pinned to today's default.

`receiveEvent` accepts server-triggered events only (`source == 65535`); a local
`TriggerEvent` under that name does nothing.

## versioncheck

`tlib.versioncheck(opts)` — the startup banner, version comparison and changelog. It is both
callable and a table, so `tlib.versioncheck(opts)` and `tlib.versioncheck.check(opts)` are
the same call, alongside `.github(repo)`, `.studios(product, current)` and `.lean(...)`.

It has its own page: see [Version Check](/docs/tLib/versioncheck).
