Consumers import `@tLib/imports.lua` and call `tlib.versioncheck` on the server.
The call is itself the load; nothing needs declaring.

```lua
local current = GetResourceMetadata(GetCurrentResourceName(), 'version', 0)
tlib.versioncheck({
    name = 'MyResource',
    current = current,
    fetch = tlib.versioncheck.github('owner/repository'),
    info = {
        { key = 'Status', event = 'myresource:startupStatus', required = true },
    },
})
```

## Providers

`fetch` is any function returning `{ version, changelog, url }`, `nil` on failure, or
`{ status = 'Update check not run' }` for a check that is deliberately unavailable. An
unavailable check must not return the installed version and claim it is current.

| Provider | Use it for |
| --- | --- |
| `tlib.versioncheck.github(repo)` | A release published on GitHub. `github(nil)` makes no request and reports that the repository is not configured. |
| `tlib.versioncheck.studios(product, current)` | A TIMMYG Studios catalogue product, through the product changelog API. Eight-second timeout. |
| your own function | Anything else — a private endpoint, a cached result you already hold. |

## Branding

Generated ASCII art, custom `banner` art, and `versioncheck.lean()` are available
only when the **calling resource's manifest** contains an author entry equal to
`TIMMYG Studios` (case-insensitive, surrounding whitespace ignored). Both repeated
`author` metadata and `authors` lists are recognized. For example:

```lua
author 'Another contributor'
author 'TIMMYG Studios'
```

The caller's folder name, `opts.name`, and `opts.author` do not grant banner eligibility.
Other consumers get a plain-name status box with version, diagnostics and update links.

<Callout type="warning" title="This is a branding convention, not proof of authenticity">
  A manifest is editable, so nothing downstream may use this rule to decide who is
  *allowed* to do something — that is what ACEs are for. The menu registry's matching
  exemption grants a studio resource room against the per-owner registration counts; it
  never grants authority, and every schema check, duplicate refusal and ACE check behaves
  identically for a trusted owner.
</Callout>

The rule lives in `shared/sh_branding.lua`, which is read from disk by the banner and by
the menu registry. It must be listed in **both** `shared_scripts` and `files` in
`fxmanifest.lua`; with only one of the two, one of the callers silently loses the rule.

## Display titles

A product's human-visible title is the manifest's own `name` directive, and nothing
else. `tELS` declares `name 'Tommy\'s ELS'`; the resource, the folder, the slug, the
event prefixes and every ACE object stay `tELS`.

```lua
name 'Tommy\'s ELS'      -- shown to people
-- the resource is still tELS everywhere else
```

`StudioBranding.displayName(resource)` reads it, falling back to the resource name when
the manifest declares nothing, declares it empty, or the metadata natives cannot answer —
so a caller only ever gets a label back, never a failure it could mistake for identity.

It is text and only text. A display title is never a slug, ACE object, event name,
command, statebag or KVP key, filename, cache key, wire field or lookup index. The
update check's request URL is keyed on the product slug, which is the technical name.

The banner prints the title as a **text line** under the wordmark rather than as art.
The figlet font has glyphs for letters and digits only — no space, no apostrophe — so
`Tommy's Radar Detector` renders as `TommysRadarDetector`, and measured it is 173
columns wide against `tDetector`'s 74, which wraps and destroys the box. So the art
keeps spelling the short technical name:

```
     _/     _/_/_/_/ _/         _/_/_/
  _/_/_/_/ _/       _/       _/
   _/     _/_/_/   _/         _/_/
  _/     _/       _/             _/
   _/_/ _/_/_/_/ _/_/_/_/ _/_/_/

              Tommy's ELS
           By TIMMYG Studios
```

Leave `name` as the technical name and the title line is omitted, which is what a
developer library wants: the name a developer types is the name they get back.

## Running the suites

From the tLib resource root:

```sh
bun run test:lua                                          # every Lua suite, discovered off disk
bun test tests/integration/versioncheck-provider.test.ts
bun run check:regression                                  # the complete gate
```

<Callout type="warning" title="Do not hand a suite to fengari yourself">
  Fengari's CLI can print an unhandled Lua error and still exit **0**, so a suite that
  blew up on its first line reads as a pass. `scripts/run-lua-suite.lua` turns that into
  a non-zero exit, so go through it even for a single suite:

```sh
bunx --bun --package fengari-node-cli fengari scripts/run-lua-suite.lua tests/lua/versioncheck.lua
```
</Callout>

The suites run the real Lua checker in a Lua VM with mocked FiveM metadata, events, HTTP
callbacks and scheduling. No live server and no credentials are needed.
